しくみ1: 関数とグラフ、傾き

関数は「数を入れると、決まった数が1つ出てくる箱」です。f(x) = 2x + 1 なら、3 を入れると 2 × 3 + 1 = 7 が出ます。機械学習のモデルも、特徴量を入れると予測が出てくる関数です。

入れる数を横軸、出てくる数を縦軸にして点を打つとグラフになります。直線のグラフ y = ax + b の a を傾きといい、「x が 1 増えたとき y がいくつ増えるか」を表します。

傾き=y の増え方x の増え方

例: 2点から傾きを求める

y = 2x + 1 の上の2点 (1, 3) と (3, 7)。x は 3 − 1 = 2 増え、y は 7 − 3 = 4 増えたので、傾きは 4 ÷ 2 = 2。式の x の前の数と一致します。

しくみ2: Σ(シグマ)と平均

たくさんの数を足すとき、「+ … +」と書くかわりに Σ を使います。

4Σi=1 xi=x1 + x2 + x3 + x4

数学メモΣ の式を言葉にする

  1. Σ「足し合わせる」という命令。
  2. 下の i = 1、上の 4番号 i を 1 から 4 まで動かす。
  3. xii 番目のデータ。i = 1 なら x1。

データが 2、5、4、7 なら Σxi = 2 + 5 + 4 + 7 = 18。範囲が明らかなときは、上下の数を省いて Σx とだけ書きます。

合計を個数 n で割ったものが平均で、x(エックスバー)と書きます。

x=Σxin

例: 平均と、平均からのずれ

  1. 2、5、4、7 の平均は 18 ÷ 4 = 4.5。
  2. 平均からのずれ(x − x)は −2.5、0.5、−0.5、2.5。足すと 0。平均からのずれは、いつも足すと 0 になります。だから「ずれの大きさ」を測るときは、2乗してから足します(分散、MSE)。

しくみ3: ベクトル、内積、長さ、コサイン類似度

ベクトルは、数をいくつか順に並べた組です。(2, 1) は「右へ 2、上へ 1」の矢印とも、「特徴量が2つあるデータ」とも見られます。並んでいる数の個数を次元といいます。LLM では、1つの単語を数百〜数千次元のベクトルで表します。

2つのベクトルの内積は、同じ位置どうしをかけて、全部足した数です。

a·b=a1b1 + a2b2 + … + anbn

ベクトルの長さ(ノルム)は、三平方の定理と同じで、各成分を2乗して足し、ルートをとります。

‖a‖=√(a12 + a22 + …)

内積は「長さ × 長さ × cos(間の角度)」と等しくなります。そこで、内積を長さの積で割ると、長さに関係なく向きの近さだけが残ります。これがコサイン類似度です。

コサイン類似度=a·b‖a‖ × ‖b‖

数学メモ内積は「同じ向きにどれだけそろっているか」

  1. a·b = 2 × 1 + 1 × 21番目どうし、2番目どうしをかけて足す。= 4。
  2. ‖a‖ = √(22 + 12)= √5 ≒ 2.24。‖b‖ も同じく √5。
  3. 4 ÷ (√5 × √5)√5 × √5 = 5 なので、コサイン類似度 = 4 ÷ 5 = 0.8。

内積が正なら同じ側を向き、0 なら直角、負なら反対側を向いています。(1, 0) と (0, 1) は 1 × 0 + 0 × 1 = 0 で直角です。(3, 4) の長さは √(9 + 16) = √25 = 5 です。

しくみ4: 行列とベクトルの積(形の決まり)

行列は、数を長方形に並べたものです。横の並びを行、縦の並びを列といい、2行3列の行列を「2×3」と書きます。行列 × ベクトルは、「行列の各行とベクトルの内積」を縦に並べたものです。

数学メモ行列の積を1行ずつ

  1. 1行目 (1, 0, 2)·(1, 2, 3)1 × 1 + 0 × 2 + 2 × 3 = 7。
  2. 2行目 (0, 1, −1)·(1, 2, 3)0 × 1 + 1 × 2 + (−1) × 3 = −1。
  3. 形 (2×3) × (3) → (2)内側の 3 と 3 がそろっていないと計算できない。答えの形は外側の数で決まる。

一般に (m×n) × (n×p) → (m×p)。たとえば (2×3) × (3×4) は 2×4 になり、(2×3) × (2×4) は内側が 3 と 2 でそろわないので計算できません。

ニューラルネットワークの全結合層は、まさに「重みの行列 × 入力ベクトル + バイアス」です。入力 3 個・出力 2 個の層なら重みの行列は 2×3 で 6 個、バイアスが 2 個です(ニューラルネットワーク)。Transformer の自己注意も、行列の積の組み合わせでできています(LLMのしくみ)。

しくみ5: 微分 = その点での傾き

曲線にも、各点ごとの傾きがあります。その点にぴったり接する直線(接線)の傾きです。これを求めることを微分といいます。学習では「重みを少し動かすと、損失がどれだけ増えるか(減るか)」を知るために微分を使います。

求め方の考え方は、「ほんの少し動かして、増え方 ÷ 動かした量 を計算する」です。

傾き≒f(x + h) − f(x)h(h はとても小さい数)

数学メモx2 の微分が 2x になるのを、数で確かめる

  1. x = 3、h = 0.1(3.12 − 32) ÷ 0.1 = (9.61 − 9) ÷ 0.1 = 6.1。
  2. x = 3、h = 0.01(3.012 − 9) ÷ 0.01 = 0.0601 ÷ 0.01 = 6.01。
  3. h → 0h を小さくするほど 6 に近づく。2x = 2 × 3 = 6 と一致する。

よく使う決まり: xn の微分は nxn−1(x2 → 2x、x3 → 3x2)。定数の微分は 0(傾きのない水平線)。3x2 のような定数倍は 3 × 2x = 6x、足し算は項ごとに微分して足します。

微分が正なら右上がり(x を増やすと増える)、負なら右下がり、0 なら山の頂上か谷の底などの平らな所です。勾配降下法は「微分が正なら x を減らし、負なら増やす」ことで谷底に向かいます(勾配降下法)。

しくみ6: 偏微分と勾配ベクトル

モデルには重みがたくさんあります。偏微分は「ほかの重みは止めて、1つの重みだけを動かしたときの傾き」です。記号 ∂(ラウンドディー)を使って ∂L/∂w1 と書きます。すべての重みの偏微分を並べたベクトルが勾配で、∇L(ナブラ L)と書きます。

数学メモL = 2w12 + w22 の勾配

  1. ∂L/∂w1 = 4w1w2 は止めた定数とみなす。w22 は定数なので微分すると 0、2w12 は 2 × 2w1。
  2. ∂L/∂w2 = 2w2今度は w1 を止める。
  3. (w1, w2) = (1, 2) で∇L = (4 × 1, 2 × 2) = (4, 4)。

勾配は「損失がいちばん急に増える向き」を指します。だから、その逆向きに動かすと損失が減ります。勾配降下法の例2が、この計算の続きです。

しくみ7: 合成関数の微分(連鎖律)

関数を順につないだもの(合成関数)の微分は、「それぞれの段の微分をかけ算する」と求まります。これが連鎖律で、ニューラルネットワークの学習(誤差逆伝播法)の土台です。

dy/dx=(dy/du) × (du/dx)

数学メモy = (3x + 1)2 を x = 1 で微分する

  1. u = 3x + 1 とおく中身に名前をつける。x = 1 なら u = 4。
  2. dy/du = 2uy = u2 の微分。u = 4 で 8。
  3. du/dx = 33x + 1 の傾き。
  4. 8 × 3 = 24かけ算で全体の傾き。数で確かめると (4.0032 − 16) ÷ 0.001 ≒ 24.009 で、ほぼ 24。

勾配降下法で出てくる (w − 3)2 の微分 2(w − 3) も、同じ考え方です(中身 w − 3 の傾きは 1)。

しくみ8: 指数関数 ex と自然対数 ln

e ≒ 2.718 は、数学でよく使う決まった数(ネイピア数)です。指数関数 ex(exp(x) とも書く)は、x が 1 増えるごとに約 2.718 倍になる関数で、どんな x でも必ず正です。e0 = 1、e1 ≒ 2.718、e2 ≒ 7.389、e−1 ≒ 0.368。ex を微分すると ex のまま、という便利な性質もあります。

自然対数 ln x はその逆で、「e を何乗すると x になるか」です。ln 1 = 0、ln e = 1。正の数にしか使えず、1 より小さい数の ln は負になります。

数学メモln の3つの性質と、損失に log を使う理由

  1. ln(a × b) = ln a + ln bかけ算が足し算になる。
  2. ln(1/p) = −ln p逆数はマイナスになる。ln 2 ≒ 0.693、ln 0.5 ≒ −0.693。
  3. 0 < p < 1 なら ln p < 0だから損失は −ln p と、マイナスをつけて正にする。

3問のそれぞれに、モデルが正解へ確率 0.9、0.8、0.5 をつけたとします。全部当たる確率はかけ算で 0.9 × 0.8 × 0.5 = 0.36。−ln 0.36 ≒ 1.022 は、1問ずつの −ln 0.9 ≒ 0.105、−ln 0.8 ≒ 0.223、−ln 0.5 ≒ 0.693 の合計と一致します。かけ算は、データが増えるとすぐ 0 に近い小さな数になって扱いにくいので、足し算にできる log を使います(交差エントロピー)。

しくみ9: 確率と条件付き確率

確率は 0 から 1 の数で、起こりうることすべての確率を足すとちょうど 1 になります。さいころで偶数が出る確率は 3 ÷ 6 = 0.5。分類モデルやソフトマックスの出力が「合計 1」になっているのは、これを守るためです。

条件付き確率 P(A | B) は、「B だとわかっているときの、A の確率」です。

P(A | B)=A と B が両方起きる確率B が起きる確率

例: メール 100 通

「無料」をふくむメールが 30 通、そのうち迷惑メールが 20 通。迷惑メールは全部で 25 通。

  1. P(迷惑 | 「無料」をふくむ) = 20 ÷ 30 ≒ 0.67。
  2. P(「無料」をふくむ | 迷惑) = 20 ÷ 25 = 0.8。
  3. 縦棒の左右を入れかえると、別の確率になります。

LLM が出しているのも条件付き確率です。「今日 は」のあとに「晴れ」が来る確率 P(晴れ | 今日 は) を計算しています。文全体の確率は、1トークンずつの条件付き確率のかけ算です。P(今日) = 0.2、P(は | 今日) = 0.5、P(晴れ | 今日 は) = 0.3 なら、「今日 は 晴れ」の確率は 0.2 × 0.5 × 0.3 = 0.03 です。

しくみ10: 期待値・分散・標準偏差

期待値 E[X] は「値 × その確率」を全部足したもので、何度もくり返したときの平均です。さいころの期待値は (1 + 2 + 3 + 4 + 5 + 6) × 1/6 = 3.5。

分散は「平均からのずれの2乗」の平均で、ばらつきの大きさを表します。標準偏差は分散のルートで、元のデータと同じ単位にもどります。

分散=Σ(xi − x)2n標準偏差 = √分散

数学メモデータ 2、4、4、4、5、5、7、9 で計算する

  1. x = 40 ÷ 8平均は 5。
  2. xi − xずれは −3、−1、−1、−1、0、0、2、4。
  3. (xi − x)2 の和9 + 1 + 1 + 1 + 0 + 0 + 4 + 16 = 32。
  4. ÷ n分散 = 32 ÷ 8 = 4、標準偏差 = √4 = 2。

データの個数ではなく n − 1 で割る書き方もあります(手元のデータから全体のばらつきを見積もるとき)。どちらで割るかで値が少し変わります。

しくみ11: 正規分布

身長や測定の誤差のように、平均のまわりに多く集まり、離れるほど少なくなる、左右対称のつりがね形の分布を正規分布といいます。平均 μ(ミュー)と標準偏差 σ(シグマ)の2つで形が決まります。σ が大きいほど低く横に広がります。

例: 平均 170、標準偏差 6 の正規分布

164〜176 に約 68%、158〜182 に約 95% が入ります。

AI では、重みの初期値をランダムに決めるときや、拡散モデルで画像に足すノイズなどに正規分布を使います(生成AIのしくみ)。

よくある誤解・注意

  • x2 と x2 はちがう。右下は「2番目」、右上は「2乗」です。
  • コサイン類似度は長さを見ない。(1, 2) と (2, 4) は長さがちがっても向きが同じなので 1 です。長さもふくめて比べたいなら内積や距離を使います。
  • 行列のかけ算は順番を入れかえられない。形がそろわないことがあり、そろっても結果が変わることがあります。
  • ln は 0 や負の数には使えない。確率 0 の ln は −∞ になるので、損失 −ln p は「正解に確率 0 をつける」と限りなく大きくなります。
  • σ は文脈で読む。σ(z) とかっこがあればシグモイド関数、分布の話なら標準偏差です。
  • P(A | B) と P(B | A) はちがう。上のメール例では 0.67 と 0.8 でした。

ひとことで

機械学習は、データから「入力 → 出力」の規則をコンピューターに見つけさせる方法です。正解つきで学ぶ・正解なしで構造を探す・報酬で行動を学ぶ、の3つに大きく分かれます。

しくみ

人が規則を1つずつ書くかわりに、たくさんの例から規則を学ばせるのが機械学習です。学び方は大きく3種類あります。

  • 教師あり学習: 入力と正解(ラベル)の組から、入力から正解を当てる規則を学ぶ。当てる値が気温や価格のような連続した数なら回帰、「猫か犬か」のように決まった種類(クラス)のどれかなら分類。
  • 教師なし学習: 正解なしで、データの中の構造を見つける。似たものどうしをまとめるクラスタリング(k-means 法など)が代表例。
  • 強化学習: エージェントが環境の中で行動し、得られる報酬の合計が大きくなるような行動の選び方(方策)を学ぶ。1つ1つの行動に正解は与えられない。

予測の手がかりとしてモデルに入れる値を特徴量、当てたい値をラベル(目的変数)といいます。家の価格の予測なら、床面積・駅からの距離・築年数が特徴量、価格がラベルです。もっとも単純な線形モデルは、特徴量に重みをかけて足し、最後にバイアスを足します。

y=w1x1 + w2x2 + … + b

数学メモ線形モデルの式を言葉にする

  1. x1、x21番目、2番目の特徴量(床面積、駅からの距離 など)。右下の数字は番号で、かけ算ではない。
  2. w1x1w1 × x1。特徴量に「どれだけ効くか」の重みをかける。
  3. + … + b特徴量の数だけ足して、最後にバイアス(底上げの数)を足す。

重みを並べた (w1, w2) と特徴量 (x1, x2) の「同じ位置どうしをかけて足す」計算は、ベクトルの内積です。重みが負なら、その特徴量が大きいほど予測は小さくなります(駅から遠いほど安い、など)。

重みやバイアスのように学習でデータから決まる値をパラメータ、学習率・エポック数・層の数のように学習の前に人が決める値をハイパーパラメータといいます。

機械学習の本当の目標は、学習に使っていない新しいデータでもうまく予測できること(汎化)です。そこで、データを役割の違う3つに分けます。

例1: 線形モデルの予測

y = 3x1 − 2x2 + 4 に、x1 = 2、x2 = 1 を入れる。

  1. 重みをかける: 3 × 2 = 6、−2 × 1 = −2。
  2. 足してバイアスを足す: 6 − 2 + 4 = 8。

例2: データの分割

2000 件を 訓練 : 検証 : テスト = 80 : 10 : 10 に分ける。

  1. 訓練: 2000 × 0.8 = 1600 件。
  2. 検証: 2000 × 0.1 = 200 件。テストも同じく 200 件。

例3: でたらめな答えの正解率(比べる基準)

4種類のクラスが同じ数ずつあるとき、4つから等しい確率で選ぶと、当たる確率は 1 ÷ 4 = 25%。作ったモデルの正解率は、このような基準より高いかどうかで見ます。

よくある誤解・注意

  • テストデータで調整しない。テストの成績を見ながら設定を変えると、テストデータに合わせこんでしまい、性能を高く見積もりすぎます。調整には検証データを使います。
  • データリークに気をつける。テストデータの一部が訓練データにまざるなど、評価用の情報が学習に入りこむと、モデルが「答えを見た」状態になり、本当の性能より良く見えます。
  • 訓練データでの誤差が 0 でも、よいモデルとは限らない。大事なのは新しいデータでの性能(汎化)です。訓練データにだけ合いすぎた状態を過学習といいます。

線形回帰は、データに直線 y = wx + b をあてはめる方法です。予測と実測のずれを損失(MSE など)で1つの数にし、それが最小になる傾きと切片を選びます。

しくみ

直線 y = wx + b の w(傾き)は「x が 1 増えたときの y の増え方」、b(切片)は「x = 0 のときの値」です。特徴量が2つ以上あっても、重みをかけて足し、切片を足すことは同じです(重回帰)。

実測値と予測値の差を残差といいます。向きに注意してください。

残差=実測値 y − 予測値 ŷ

残差が正なら、モデルは実際より小さく予測しています。モデルの悪さを1つの数にまとめたものが損失関数で、学習とは損失が小さくなるようにパラメータを調整することです。回帰でよく使う損失・指標は次のとおりです(n はデータの件数)。

MSE=(残差の2乗の和)n
MAE=(残差の絶対値の和)n
RMSE=√MSE

数学メモMSE を Σ で書いて、1行ずつ読む

MSE=1n Σ(yi − ŷi)2
  1. yi − ŷii 番目のデータの残差(実測 − 予測)。ŷ(ワイハット)は予測値。
  2. ( … )22乗して、マイナスをなくす。
  3. Σ全データぶん足す(Σ の読み方)。
  4. 1n件数で割って平均にする。

なぜ2乗するのか。下の例1の直線の残差は −0.4、1.2、−1.2、0.4 で、そのまま足すと 0 になり、「ずれがない」ように見えてしまいます。2乗すれば 0.16 + 1.44 + 1.44 + 0.16 = 3.2 と、ずれの大きさが残ります。2乗には、2倍のずれを4倍の罰にする(大きな外れを重く見る)効果と、微分しやすい(微分)という利点もあります。

MSE(平均二乗誤差)は誤差を2乗するので、大きな誤差ほど強く効きます。MAE(平均絶対誤差)は外れ値の影響を受けにくい指標です。RMSE は誤差と同じ単位にもどるので、「だいたい何ずれるか」をつかみやすくなります。

残差の2乗の和が最小になるように傾きと切片を決めるのが最小二乗法です。線形回帰では、最小値を与える係数を式で直接求められます(x、y は平均)。

w = Σ(x − x)(y − y)Σ(x − x)2b = y − wx

数学メモ傾き w の式を読む

  1. x、yエックスバー、ワイバー。x と y の平均。
  2. (x − x)(y − y)1点ごとに「x の平均からのずれ × y の平均からのずれ」。両方が平均より大きい(または両方小さい)点は正、片方だけなら負になる。
  3. 分子の Σそれを全部足す。正が多ければ「x が大きいと y も大きい」右上がりの関係。
  4. 分母 Σ(x − x)2x のばらつき。これで割って、x 1 あたりの増え方(傾き)にそろえる。
  5. b = y − wx直線が平均の点 (x, y) を通るように切片を決める。

当てはまりのよさは決定係数 R2 でも表します。「いつも平均で予測する」ときと比べて、誤差をどれだけ減らせたかの割合です。

R2=1 − 残差の2乗和平均からのずれの2乗和

例で確かめる

例1: 図の直線を最小二乗法で求め、MSE と R2 を出す

  1. 平均: x = 2.5、y = (2 + 5 + 4 + 7) ÷ 4 = 4.5。
  2. Σ(x − x)(y − y) = (−1.5)(−2.5) + (−0.5)(0.5) + (0.5)(−0.5) + (1.5)(2.5) = 7、Σ(x − x)2 = 5。
  3. w = 7 ÷ 5 = 1.4、b = 4.5 − 1.4 × 2.5 = 1。直線は ŷ = 1.4x + 1。
  4. 予測は 2.4、3.8、5.2、6.6。残差は −0.4、1.2、−1.2、0.4。2乗の和は 0.16 + 1.44 + 1.44 + 0.16 = 3.2。
  5. MSE = 3.2 ÷ 4 = 0.8。RMSE = √0.8 ≒ 0.89。
  6. 平均からのずれの2乗和 = 2.52 + 0.52 + 0.52 + 2.52 = 13。R2 = 1 − 3.2 ÷ 13 ≒ 0.75。

例2: 外れ値に強いのはどちらか

4件の誤差が「1, 1, 1, 1」のモデル A と、「0, 0, 0, 4」のモデル B を比べる。

  1. MAE: A は 4 ÷ 4 = 1、B も 4 ÷ 4 = 1 で同じ。
  2. MSE: A は 4 ÷ 4 = 1、B は 16 ÷ 4 = 4。1件の大きな外れが、MSE では4倍の差になる。

例3: 定数で予測するときの最良の値

どの入力にも同じ値 c を予測するとき、データ 1、2、9 に対して MSE を最小にするのは平均 (1 + 2 + 9) ÷ 3 = 4、MAE を最小にするのは中央値 2 です。

よくある誤解・注意

  • 残差の向き。残差は「実測 − 予測」です。逆にすると符号が反対になります(2乗する MSE の値は変わりません)。
  • 残差に形が見えたら要注意。直線でうまく表せていれば、残差は 0 のまわりに規則なく散らばります。残差を x に対して並べて U 字形などが見えるなら、関係が直線ではなく曲線的です。
  • 傾きは「関係」を表すだけ。「勉強時間が1時間増えると予測点数が3点上がる」は予測の読み方で、勉強すれば必ずそうなるという因果を示すものではありません。
  • R2 の範囲。訓練データに最小二乗で合わせた直線(切片あり)では 0〜1 になりますが、別のデータで測ると、平均で予測するより悪ければ負にもなります。

勾配降下法は、損失の坂の傾き(勾配)を調べ、その逆向きに少しずつパラメータを動かして、損失の谷底を探す方法です。1歩の大きさは学習率 η で決まります。

しくみ

損失 L を重み w で微分した値(勾配)は、w を増やしたときに損失が増える向きと急さを表します。損失を減らしたいので、勾配の逆向きに進みます。

w←w − η × (L の w による微分)

数学メモ更新の式を1行ずつ

  1. (L の w による微分)w を少し増やしたとき L がどれだけ増えるか(その点での傾き)。正なら右上がり、負なら右下がり(微分)。
  2. η ×イータ(学習率)をかけて、1歩の大きさにする。
  3. w − …傾きと反対向きに動かす。傾きが正なら w は減り、負なら増える。
  4. ←計算した値で w を置きかえる。これを何度もくり返す。

例: 傾きが 6、η = 0.1 なら w は 0.6 減ります。傾きが −6 なら 0.6 増えます。ほかの本では w ← w − η ∂L/∂w、まとめて θ ← θ − η∇L とも書きます(偏微分と勾配)。

坂が急なほど1歩が大きく、谷底(勾配 0)に近づくほど1歩が小さくなります。パラメータが複数あるときは、それぞれの微分(偏微分)の分だけ、パラメータごとに動かします。

学習率 η の決め方が大切です。損失 L = w2 で考えると、微分は 2w なので、1歩は次のように書けます。

w←w − η × 2w = (1 − 2η)w

毎回 (1 − 2η) 倍になるので、|1 − 2η| < 1、つまり 0 < η < 1 のときに 0 へ収束します。

η1歩でかかる倍率w = 1 からの動きようす
0.10.81 → 0.8 → 0.64まっすぐ近づく(ゆっくり)
0.501 → 01歩で最小に着く
0.75−0.51 → −0.5 → 0.25谷をはさんで行き来しながら近づく

損失が (w − 3)2 のように谷底がずれていても、「谷底からの距離」が毎回 (1 − 2η) 倍になるので、同じことがいえます。

数学メモ(w − 3)2 の微分が 2(w − 3) になるわけ

  1. 中身 u = w − 3L = u2 の微分は 2u。
  2. u の w による微分 = 1w が 1 増えると w − 3 も 1 増える。
  3. 2u × 1= 2(w − 3)。かけ算でつなぐのが連鎖律。

w = 0 なら 2 × (0 − 3) = −6(右下がり)、w = 3 なら 0(谷底で平ら)、w = 5 なら 4(右上がり)。

実際の学習では、データを小分けにしたミニバッチごとに勾配を計算して更新します(確率的勾配降下法、SGD)。訓練データ全体を1回ずつ使い切ることを1エポックといい、1エポックの更新回数は「データ数 ÷ ミニバッチの大きさ」です(割り切れる場合)。一部のデータで勾配を見積もるので1回の計算は軽いかわりに、勾配に「ばらつき」がまざります。

勾配降下法を改良した方法もよく使われます。モメンタムは、これまでの勾配を「速度」のようにためて使い、同じ向きには加速し、行き来する振動は打ち消し合っておさえます。Adam は、勾配の移動平均(モメンタムに近いもの)と、勾配の2乗の移動平均を組み合わせ、パラメータごとに1歩の大きさを調整します。勾配の大きさで割るので、勾配が大きいパラメータでも飛びすぎず、1歩はおよそ η 程度にそろいます。勾配の向きが行き来してばらつくパラメータでは、分子の平均が打ち消し合って小さくなり、1歩も小さくなります。

Adam(おおまかな形)w ← w − η × (勾配の移動平均)√(勾配の2乗の移動平均) + ε

実際には、最初のうちの値のかたよりを直す補正も入ります。ε は 0 で割らないための小さな数です。

例で確かめる

例1: L = (w − 3)2、w = 0、η = 0.25(上の図)

  1. 微分は 2(w − 3)。w = 0 では 2 × (0 − 3) = −6(負なので、w を増やす向きが下り坂)。
  2. w ← 0 − 0.25 × (−6) = 1.5。
  3. 次の勾配は 2 × (1.5 − 3) = −3。w ← 1.5 − 0.25 × (−3) = 2.25。以後 2.625、2.8125 … と 3 に近づく。

例2: パラメータが2つ

L = 2w12 + w22、(w1, w2) = (1, 2)、学習率 0.1。

  1. 勾配は (4w1, 2w2) = (4, 4)。
  2. (1 − 0.1 × 4, 2 − 0.1 × 4) = (0.6, 1.6)。

例3: データ1件で重みを更新する

x = 3、y = 4、モデル ŷ = wx、損失 L = (ŷ − y)2、w = 2、学習率 0.01。

  1. 予測 ŷ = 2 × 3 = 6。
  2. 勾配 = 2(ŷ − y) × x = 2 × (6 − 4) × 3 = 12。
  3. w ← 2 − 0.01 × 12 = 1.88。予測が大きすぎたので w が小さくなった。

例4: 1エポックの更新回数

訓練データ 6000 件、ミニバッチ 100 件なら、6000 ÷ 100 = 60 回。10 エポック学習すると 600 回更新します。

よくある誤解・注意

  • 符号はマイナス。勾配は損失が増える向きを指すので、「w − η × 勾配」です。プラスにすると坂を登ります。
  • 学習率は大きければ速い、とは限らない。大きすぎると谷を飛びこえて振動したり発散したりします。小さすぎると、正しい向きでも1歩がわずかで、収束が遅くなります。
  • 止まった場所が一番低いとは限らない。谷が複数あると、浅い谷の底(局所解)で止まることがあります。そこでは勾配が 0 なので、それ以上動きません。どの谷に着くかは初期値などで変わります。

しくみ

2つのクラス(陽性・陰性)に分ける代表的な方法がロジスティック回帰です。まず線形モデルで z = wx + b を計算し、それをシグモイド関数に通して「陽性の確率」にします。

σ(z)=11 + e−z

σ(z) は z が大きいと 1 に、小さいと 0 に近づきますが、どちらにも届きません(値は 0 より大きく 1 より小さい)。σ(0) = 0.5 で、点 (0, 0.5) について対称な形なので σ(−z) = 1 − σ(z) が成り立ちます。σ(z) が 0.5 より大きいのは z > 0 のときなので、z = 0 になるところが「確率 50%」の境目です。

数学メモシグモイドの式を、内側から読む

  1. e−ze ≒ 2.718 の −z 乗。必ず正(指数関数)。z が大きいほど 0 に近く、z が負で大きいほど巨大になる。
  2. 1 + e−z1 より大きい数。
  3. 1 ÷ ( … )1 より大きい数で 1 を割るので、答えは 0 と 1 の間におさまる。

z = 0: e0 = 1 なので 1 ÷ (1 + 1) = 0.5。z = 2: e−2 ≒ 0.135 なので 1 ÷ 1.135 ≒ 0.88。z = −2: e2 ≒ 7.389 なので 1 ÷ 8.389 ≒ 0.12。どんな数を入れても「確率らしい」0〜1 の値になるのが、分類で使われる理由です。

学習の損失には交差エントロピーを使います。正解のクラスにモデルがつけた確率を p とすると、損失は −ln p(ln は自然対数)。2クラスで正解が陽性なら −ln(陽性の確率)、陰性なら −ln(1 − 陽性の確率)です。p が 1 に近いほど損失は 0 に近く、正解に低い確率をつける(自信をもって間違える)ほど、上限なく大きくなります。

正解のクラスの確率 p損失 −ln p
0.9≒ 0.11
0.5≒ 0.69
0.1≒ 2.30
0.01≒ 4.61

数学メモ−ln p を読む

  1. p正解のクラスにモデルがつけた確率(0 より大きく 1 以下)。
  2. ln p自然対数。p < 1 なら負の数、p = 1 なら 0(ln)。
  3. −マイナスをつけて正の数にする。損失は「小さいほどよい」数にしたいため。

確率が半分になるごとに、損失は ln 2 ≒ 0.69 ずつ増えます(0.5 → 0.69、0.25 → 1.39)。データが複数あるときは、1件ずつの −ln p の平均を損失にします。これは「全部当たる確率」のかけ算を、ln で足し算に直したものです。

判定は「陽性の確率(スコア)がしきい値以上なら陽性」とします。結果を数えた表が混同行列で、行が実際、列が予測です。TP・FN・FP・TN の頭の T/F は予測が当たったか外れたか、P/N は予測の側の答えを表します。

  • 正解率 = (TP + TN) ÷ 全体。
  • 適合率 = TP ÷ (TP + FP)。陽性と予測したもののうち、本当に陽性だった割合(誤検出 FP の少なさ)。
  • 再現率 = TP ÷ (TP + FN)。実際に陽性のもののうち、陽性と見つけられた割合(見逃し FN の少なさ)。
  • F1 スコア = 2 × 適合率 × 再現率 ÷ (適合率 + 再現率) = 2TP ÷ (2TP + FP + FN)。適合率と再現率の調和平均。

しきい値を上げると、陽性と判定するデータは減るか同じなので、TP も減るか同じで、再現率は下がるか変わりません。かわりに誤検出(FP)が減りやすく、適合率は上がることが多くなります(必ずではありません)。しきい値を下げると逆です。どこに置くかは目的しだいです。

例で確かめる

例1: 混同行列から4つの指標を出す

  1. 正解率 = (45 + 35) ÷ 100 = 0.80。
  2. 適合率 = 45 ÷ (45 + 5) = 0.90。
  3. 再現率 = 45 ÷ (45 + 15) = 0.75。
  4. F1 = 2 × 45 ÷ (2 × 45 + 5 + 15) = 90 ÷ 110 ≒ 0.82。

例2: ロジスティック回帰の境目

z = 0.5x − 3、σ(z) ≥ 0.5 なら陽性と判定するとき。

  1. σ(z) ≥ 0.5 になるのは z ≥ 0 のとき(σ(0) = 0.5)。
  2. 0.5x − 3 ≥ 0 より x ≥ 6 で陽性と判定する(x = 6 では陽性の確率がちょうど 50%)。

例3: 不均衡なデータ

1000 件のうち陽性が 20 件(2%)のデータで、すべて「陰性」と答えるモデルは、陰性 980 件がすべて当たるので正解率 98%。でも陽性を1件も見つけていないので、再現率は 0% です。

よくある誤解・注意

  • 正解率が高い = よいモデル、とは限らない。陽性がとても少ない不均衡データでは、全部「陰性」でも正解率が高くなります。再現率や適合率もあわせて見ます。
  • FP と FN を取りちがえない。FP(偽陽性)は「実際は陰性なのに陽性と予測」、FN(偽陰性)は「実際は陽性なのに陰性と予測(見逃し)」。
  • 何を重視するかは目的しだい。病気の検査で見逃し(FN)を減らしたいなら再現率、迷惑メールの判定で大事なメールを捨てたくない(FP を減らしたい)なら適合率を重視します。
  • −1〜1 になるのは tanh。シグモイドの値は 0〜1 の間(両端はふくまない)です。

ひとことで

過学習は、訓練データの細かいくせ(ノイズ)まで覚えてしまい、新しいデータで外れる状態です。正則化・ドロップアウト・早期終了・データ拡張などで抑え、検証データで確かめます。

しくみ

モデルの状態は、訓練データと検証データの誤差を並べるとわかります。

状態訓練誤差検証誤差主な原因
未学習大きい大きいモデルが単純すぎる
ちょうどよい小さい小さい(訓練との差も小さい)—
過学習とても小さい大きい(差が大きい)モデルが複雑すぎる・データが少ない

この2つの失敗はバイアスとバリアンスで説明できます。バイアスは、モデルが単純すぎるために生じる系統的なずれ(未学習側)。バリアンスは、訓練データが少し変わるだけで予測が大きく変わる、ばらつき(過学習側)です。二乗誤差の期待値は次のように分けられます。

二乗誤差の期待値=バイアス2 + バリアンス + 減らせないノイズ

「期待値」は、いろいろな訓練データで学習したときの平均、という意味です(期待値・分散)。

モデルを複雑にするとバイアスは減りやすく、バリアンスは増えやすくなります。過学習をおさえる主な方法は次のとおりです。

  • 正則化: 損失に「重みの大きさ」の罰を足す。係数 λ が大きいほど、重みを小さくする力が強い。
    L2: λ × (w12 + w22 + …)L1: λ × (|w1| + |w2| + …)
    L2 正則化(Ridge)は重みを全体に小さくしますが、ちょうど 0 にはなりにくい。L1 正則化(Lasso)はいくつかの重みがちょうど 0 になりやすく(スパース)、使う特徴量をしぼりこめます。

    数学メモ正則化つきの損失を読む

    全体の損失=もとの損失(MSE など) + λ × (w12 + w22 + …)
    1. もとの損失データに合っているか。
    2. w12 + w22 + …重みの大きさ。2乗するので、正でも負でも大きな重みほど罰が大きい。L1 なら |w|(絶対値: 符号をとった大きさ)。
    3. λ ×ラムダ。2つの「合わせる力」と「小さく保つ力」のどちらを重く見るかのつまみ。

    重み 3 は L2 で 9、L1 で 3 の罰。重み 0.5 は L2 で 0.25、L1 で 0.5。L2 は大きな重みを強くおさえ、小さな重みにはあまり効きません。L1 は大きさに関係なく同じ量ずつ 0 へ押すので(勾配は λ × 符号で一定)、小さな重みは 0 まで押し切られやすくなります。

  • ドロップアウト: 訓練中に、ランダムに選んだニューロンの出力を 0 にして学習する。特定のニューロンにたよりすぎるのを防ぐ。推論(予測)のときはふつう全ニューロンを使い、出力の大きさが訓練時とそろうように調整する。
  • 早期終了: エポックごとに検証誤差を見て、下がらなくなったところで学習を止め、検証誤差が最小のときのモデルを使う。
  • データ拡張: 意味(正解ラベル)が変わらない範囲で画像を少し回す・ずらす・明るさを変えるなどして、訓練データを増やす。

データが少ないときの評価には交差検証を使います。k 分割交差検証では、データを k 個に分け、1つを検証、残りを訓練に使う学習を、検証に使う1つを入れかえながら k 回行い、成績の平均で評価します。

  2. L1: |1| + |−2| + |2| = 5。0.5 × 5 = 2.5。

よくある誤解・注意

  • 訓練誤差だけで良し悪しを決めない。多項式の次数を上げると、高い次数は低い次数の式をふくむので訓練誤差は増えません。でもテスト誤差は、ある次数から上がりはじめます。
  • 正則化は強ければよい、ではない。λ を大きくしすぎると、必要な重みまで抑えられて未学習になります。
  • データ拡張は意味を変えない範囲で。手書き数字を180度回すと「6」が「9」のように見え、正解ラベルと合わなくなります。
  • ドロップアウトは訓練中だけ。推論のたびにランダムにニューロンを消すわけではありません。

ひとことで

ニューラルネットワークは、「重み付き和 → 活性化関数」をするニューロンを層にして重ねたモデルです。誤差逆伝播法で全部の重みの勾配を求め、勾配降下法で学習します。

しくみ

1つのニューロンは、入力に重みをかけて足し、バイアスを足した重み付き和 z を、活性化関数 φ に通して出力します。

z = w1x1 + w2x2 + … + b出力 = φ(z)

重みは入力の効き方を、バイアスは出力が切りかわる位置(しきい値)を調整します。たとえば z = wx + b が 0 になるのは x = −b ÷ w なので、b を変えると境目が動きます。

いちばん古い形のパーセプトロンは、活性化関数にステップ関数(z > 0 なら 1、そうでなければ 0)を使います。重みとバイアスを選ぶと AND や OR を表せますが、1層(直線1本で分ける)では XOR は表せません。(0,1)・(1,0) と (0,0)・(1,1) を直線1本では分けられないからです。層を重ねる(多層パーセプトロン)と表せます。

層の間に活性化関数が必要なのは、それが非線形だからです。線形変換は何回重ねても、まとめると1つの線形変換になってしまいます。間に非線形な関数をはさむことで、曲がった複雑な関係を表せるようになります。

隣の層のすべてのニューロンとつながる層を全結合層といいます。パラメータの数は次のとおりです。

全結合層のパラメータ数=入力数 × 出力数(重み) + 出力数(バイアス)

数学メモ層の計算は「行列 × ベクトル + バイアス」

z=Wx + b出力 = φ(z)
  1. x(入力数 3)入力を並べたベクトル。
  2. W(4×3)重みの行列。行が出力のニューロン1個ぶん、列が入力1個ぶん。4 × 3 = 12 個(行列の形)。
  3. Wx + b(4×3) × (3) → 4 個の重み付き和。そこにバイアス 4 個を足す。
  4. φ( … )ファイ。活性化関数を1つずつにかける。

下の図の 3 → 4 の層は、重み 12 + バイアス 4 = 16 個。ニューロン1個ずつ書いた式を、行列でまとめて書いたものです。

学習では、損失を各重みで微分した値(勾配)が必要です。誤差逆伝播法(バックプロパゲーション)は、出力側から入力側へ、連鎖律(合成関数の微分)で微分をかけ合わせて、すべての重みの勾配を効率よく求めます。求めた勾配で、勾配降下法によって重みを更新します。

L の w による微分=(L の z による微分) × (z の w による微分)

数学メモ連鎖律の式を記号で書くと

∂L∂w=∂L∂z × ∂z∂w
  1. ∂L/∂w「w を少し動かしたら、損失 L がどれだけ変わるか」。∂ はラウンドディー(偏微分)。分数のように見えるが、これで1つの記号。
  2. ∂L/∂z「重み付き和 z が変わると L がどれだけ変わるか」。出力側から先に求まる。
  3. ∂z/∂wz = wx + b なので、w が 1 増えると z は x 増える。つまり x。

「w の小さな変化が z を x 倍で動かし、z の変化が L を ∂L/∂z 倍で動かす」ので、全体の倍率はかけ算です。下の例3では −3 × 3 = −9。層が増えても、かけ算の段が増えるだけです(連鎖律)。

層が深いと、逆伝播で微分を何度もかけ合わせるうちに勾配がとても小さくなり、入力に近い層が学習しにくくなることがあります(勾配消失)。シグモイドの微分 σ(z)(1 − σ(z)) は最大でも 0.25(z = 0 のとき)なので起こりやすく、ReLU は正の範囲で微分が 1 なので起こりにくくなります。ほかに、層を飛びこす経路をつくる残差接続、重みの初期値の工夫、バッチ正規化なども使われます。

数学メモ小さな数を何度もかけると

  1. σ′(0) = 0.5 × (1 − 0.5)σ′ はシグモイドの微分(傾き)。= 0.25 で、z = 0 のここが最大。σ′(2) ≒ 0.88 × 0.12 ≒ 0.105 とさらに小さい。
  2. 0.25 × 0.25 × …(10 層)0.2510 ≒ 0.00000095。入力に近い層には、勾配がほとんど届かない。
  3. ReLU の傾き 1正の範囲なら 1 × 1 × … = 1 で、小さくならない。

例1: パーセプトロンで OR と AND(z > 0 なら 1)

重み (1, 1) のまま、バイアスだけを変える。

例2: 小さなネットワークの順伝播(中間層は ReLU、出力層は活性化なし)

入力 (x1, x2) = (2, 1)。

  1. h1 = ReLU(1 × 2 + 1 × 1 − 2) = ReLU(1) = 1。
  2. h2 = ReLU(−1 × 2 + 1 × 1) = ReLU(−1) = 0(負は 0)。
  3. y = 3 × h1 − 2 × h2 + 1 = 3 − 0 + 1 = 4。

例3: 連鎖律で勾配を求める

z = wx + b、L = (z − t)2、x = 3、w = 0.5、b = 1、正解 t = 4。

  1. z = 0.5 × 3 + 1 = 2.5。
  2. L の z による微分 = 2(z − t) = 2 × (2.5 − 4) = −3。
  3. z の w による微分は x = 3。連鎖律で −3 × 3 = −9。(b による微分は −3 × 1 = −3)

例4: パラメータの数

入力 10 → 中間層 5 → 出力 3: (10 × 5 + 5) + (5 × 3 + 3) = 55 + 18 = 73。バイアスを数え忘れると 65 になる。

よくある誤解・注意

  • 層を増やすだけでは表現力は増えない。活性化関数がない(線形のまま)なら、何層重ねても1層の線形変換と同じです。
  • パラメータ数にはバイアスも入る。出力1つにバイアス1個です。
  • 値の範囲を取りちがえない。シグモイドは 0〜1、tanh は −1〜1、ステップは 0 か 1、ReLU は 0 以上で上限なし。
  • 誤差逆伝播法は「勾配の求め方」。重みを動かすのは、その勾配を使う勾配降下法です。

CNN は小さなフィルタを画像全体で使い回して模様を見つけ、RNN は系列を前から順に処理し、Transformer は自己注意で系列のすべての位置どうしを一度に見比べます。

しくみ: CNN(畳み込みニューラルネットワーク)

畳み込みは、小さなフィルタ(例: 3×3)を画像の上で少しずつずらしながら、重なった位置どうしをかけて足し、1つの値を出す操作です。フィルタの重みは画像のすべての位置で共通(重み共有)なので、全結合層よりずっと少ないパラメータで済み、同じ模様がどこにあっても見つけられます。

出力の大きさは、入力の1辺 N、フィルタの1辺 F、パディング(まわりに足す 0 の幅)P、ストライド(ずらす幅)S で決まります。

出力の1辺=(N − F + 2P) ÷ S + 1

割り切れないとき、多くの実装では小数点以下を切り捨てます。

数学メモ出力の大きさの式を、数えて確かめる

  1. N + 2Pパディング後の1辺。両側に足すので 2 倍。5 + 0 = 5。
  2. − Fフィルタが最初に置ける位置から、最後に置ける位置まで動ける距離。5 − 3 = 2。
  3. ÷ S1回に S ずつ動くので、動ける回数。2 ÷ 1 = 2。
  4. + 1最初の位置の1つを足す。2 + 1 = 3。上の図のとおり、左端・中・右端の3か所に置ける。

畳み込み層のパラメータ数は、フィルタ1個の重み(F × F × 入力チャンネル数)× フィルタの数(出力チャンネル数)+ バイアス(フィルタ1個に1個)です。畳み込みのあとには、領域ごとに最大値を残す最大値プーリング(平均をとるなら平均値プーリング)で、特徴マップを小さくすることがよくあります。プーリングには学習するパラメータがありません。

しくみ: RNN と LSTM

RNN(再帰型ニューラルネットワーク)は、文章や時系列のような順番のあるデータを前から1つずつ処理し、前の時刻の隠れ状態を次の時刻に渡します。長い系列では、遠い過去の情報が勾配消失で伝わりにくいことがあります。LSTM は、情報の通り道であるセル状態と、そこに残す情報・捨てる情報を調節するゲート(忘却・入力・出力)を持ち、長い依存関係を学びやすくしたものです。

しくみ: Transformer と自己注意

Transformer の中心は自己注意(self-attention)です。各トークンからクエリ q・キー k・バリュー v の3つのベクトルを作り、次の手順で情報を集めます。

  1. あるトークンのクエリと、系列の各トークンのキーの内積をとり、√d(d はベクトルの次元)で割って「関連の強さ」のスコアにする。
  2. スコアをソフトマックスで重み(合計 1)にする。
  3. 各トークンのバリューを、その重みで重み付き平均する。これが出力。
スコア=q と k の内積√d

√d で割るのは、次元が大きいと内積が大きくなりやすく、ソフトマックスが1つに極端に集中するのを防ぐためです。

数学メモスコアの式を1行ずつ

  1. q と k の内積同じ位置どうしをかけて足す。向きがそろっているほど大きい(内積)。q = (1, 2)、k = (1, 1) なら 1 + 2 = 3。
  2. ÷ √dd = 2 なら √2 ≒ 1.414 で割って、3 ÷ 1.414 ≒ 2.12。
  3. なぜ √d か内積は d 個の積の和なので、成分がランダムな値なら、次元が4倍になると値のばらつき(標準偏差)はおよそ2倍(√4)になる。√d で割ると、次元によらず同じくらいの大きさにそろう。

行列でまとめた書き方 softmax(QKT ÷ √d)V は、LLMのしくみでくわしく読みます。

自己注意では、離れた位置のトークンどうしも1回で直接参照できます。そのかわり、長さ n の系列では n × n 組の重みを計算するので、長さが2倍になると4倍になります。また、自己注意はトークンの並びを入れかえても同じように計算されるので、並び順を区別するために位置エンコーディング(位置を表すベクトルを埋め込みに足す、などの方法)で位置の情報を加えます。

トークンは最初に埋め込みで、単語ごとに1本のベクトルに変えます。埋め込み表のパラメータ数は 語彙数 × 次元 です。意味の近い語は近い向きのベクトルになるように学習され、向きの近さはコサイン類似度(内積 ÷ 長さの積。−1〜1)で測ります(内積とコサイン類似度)。Transformer が LLM の中でどう組み立てられているかは、LLMのしくみで順に見ます。

例で確かめる

例1: 畳み込みの出力の大きさ(入力 64×64)

  1. 3×3、パディング 0、ストライド 1: (64 − 3 + 0) ÷ 1 + 1 = 62。
  2. 5×5、パディング 2、ストライド 1: (64 − 5 + 4) ÷ 1 + 1 = 64(大きさが変わらない)。
  3. 4×4、パディング 1、ストライド 2: (64 − 4 + 2) ÷ 2 + 1 = 31 + 1 = 32(およそ半分)。

例2: 畳み込みと最大値プーリングを計算する

  1. 左上: 左の列 (2 + 0 + 1) × 1 + 中の列 × 0 + 右の列 (0 + 3 + 2) × (−1) = 3 − 5 = −2。
  2. 1つ右へずらして同じように計算すると −1。出力は (4 − 3) ÷ 1 + 1 = 2 で 2×2。
  3. 最大値プーリング: 2×2 の領域 [1, 3; 4, 2] なら最大の 4 を残す(平均値プーリングなら 2.5)。

例3: 自己注意の重み(上の図の数値)

クエリ q = (1, 2)、キー「猫」(1, 0)・「が」(0, 1)・「鳴いた」(1, 1)、d = 2。

  1. 内積は 1、2、3。√2 ≒ 1.414 で割ると、スコアは ≒ 0.71、1.41、2.12。
  2. ソフトマックスで重みにすると ≒ 0.14、0.28、0.58(合計 1)。
  3. バリューが「猫」(10, 0)・「が」(0, 10)・「鳴いた」(5, 5) なら、出力 ≒ 0.14 × (10, 0) + 0.28 × (0, 10) + 0.58 × (5, 5) ≒ (4.3, 5.7)。

例4: パラメータ数・計算量・類似度

  1. 入力 16 チャンネルに 3×3 のフィルタを 32 個: 3 × 3 × 16 × 32 + 32 = 4640。
  2. 系列の長さ 1000 → 2000: 注意の重みは 1,000,000 → 4,000,000 で 4倍。
  3. 語彙 30000、次元 512 の埋め込み表: 30000 × 512 = 15,360,000。
  4. (1, 0) と (1, 1) のコサイン類似度: 1 ÷ (1 × √2) ≒ 0.71。(1, 2) と (−2, 1) は内積 0 で直角なので 0。

よくある誤解・注意

  • パディングは2倍する。出力の式は 2P(両側に足すため)。
  • バイアスはフィルタ1個に1個。チャンネルごとではありません。
  • CNN の「畳み込み」は、フィルタを反転しない。数学の畳み込みとは少し違い、正確には相互相関という計算ですが、慣習で畳み込みと呼びます。
  • 自己注意だけでは順番がわからない。そのために位置エンコーディングがあります。
  • コサイン類似度は長さを見ない。(1, 2) と (2, 4) は長さが違っても向きが同じなので 1 です。

ひとことで

生成AIは、データがどう分布しているかを学び、そこから新しいデータを作るモデルです。大規模言語モデル(LLM)は「次のトークンの確率」を計算して1つ選ぶ、をくり返して文章を作り、画像生成でよく使われる拡散モデルは、ノイズから少しずつノイズを取り除いて画像を作ります。

しくみ: 生成モデルと識別モデル

これまでの単元の分類モデルは、入力 x を見て答え y を当てる識別モデルでした。確率でいえば P(y | x)(「このメールが与えられたとき、迷惑メールである確率」)を学びます(条件付き確率)。

生成モデルは、データそのものがどう分布しているか(どんな文章・画像が「ありそう」か)を学び、そこから新しいデータをサンプリング(確率に従って取り出す)できるモデルです。「猫の絵」「やさしい口調で」のような条件をつけて、P(データ | 条件) から作ることもよくあります。

識別モデル生成モデル
学ぶもの入力 → 答えデータの分布
出力ラベルや確率新しい文章・画像など
例迷惑メールの判定、画像の分類LLM、拡散モデル

生成モデルには、LLM のような自己回帰モデルと拡散モデルのほかに、作る側と見分ける側を競わせる GAN(敵対的生成ネットワーク)や、データを小さな表現に圧縮して戻す VAE(変分オートエンコーダ)などもあります。

しくみ: 次トークン予測と自己回帰

LLM は文章をトークン(単語・単語の一部・文字などの小さな単位)に区切り、トークンの番号の列として扱います。どこで区切るかはモデルのトークナイザーで決まり、1文字が1トークンとも、1単語が1トークンとも限りません。

事前学習では、大量のテキストで「次のトークンは何か」を当てる次トークン予測をくり返します。正解は文章そのものの中にあるので、人がラベルをつけなくても学習できます。多くの LLM は Transformer を使い、予測のときに先のトークンを見ないようにして学習します。トークンの区切り方や、Transformer の中の計算はLLMのしくみで説明します。

文章を作るときは、予測した確率から次のトークンを1つ選んで入力の後ろに加え、それをもとにまた次を予測する、をくり返します(自己回帰生成)。10 トークン作るには、次トークン予測を 10 回行います。

  1. 入力「今日の天気は」→ 次のトークンの確率を計算 → 「晴れ」を選ぶ。
  2. 入力「今日の天気は晴れ」→ 次の確率を計算 → 「です」を選ぶ。
  3. 終わりを表すトークンが選ばれるか、長さの上限に達するまで続ける。

モデルは候補ごとのスコア(ロジット)を出し、ソフトマックスで確率にします。温度 T つきでは、ロジットを T で割ってから確率にします(T = 1 なら元のまま)。

候補 i の確率=exp(zi ÷ T)すべての候補の exp(z ÷ T) の和

exp(a) は ea(e ≒ 2.718 の a 乗)、zi は候補 i のロジット。

数学メモソフトマックスを1行ずつ(ロジット 2、1、0、T = 1)

  1. exp( … )それぞれ e の何乗かにする: e2 ≒ 7.389、e1 ≒ 2.718、e0 = 1。負のロジットでも必ず正になる(指数関数)。
  2. 分母: すべての和7.389 + 2.718 + 1 ≒ 11.107。
  3. 分子 ÷ 分母7.389 ÷ 11.107 ≒ 0.67、2.718 ÷ 11.107 ≒ 0.24、1 ÷ 11.107 ≒ 0.09。全体で割るので合計は 1。
  4. ÷ T温度があるときは、exp の前にロジットを T で割るだけ。

なぜ exp を使うのか。ロジットの差が 1 あると、確率の比は e ≒ 2.718 倍になります(晴れ ÷ 曇り = 7.389 ÷ 2.718 ≒ 2.718)。差が 2 なら e2 ≒ 7.4 倍。「差」を「倍率」に変えるので、全部に同じ数を足しても確率が変わらない、という性質が出てきます。

どの候補の確率も 0 より大きく、合計は 1 です。すべてのロジットに同じ数を足しても、分子も分母も同じ倍率になるので確率は変わりません。確率を決めるのはロジットどうしの差です。T を小さくするとロジットの差が広がり、最大の候補に確率が集中します。T を大きくすると差が縮まり、確率は均等に近づいて、出力が多様になります。

確率からの選び方にも種類があります。

  • 貪欲法: 毎回、最も確率の高いトークンを選ぶ。ランダムさがなく、同じ入力なら同じ出力になる。温度を 0 に近づけたときの選び方に近い。
  • top-k: 確率の大きい上位 k 個だけを残し、合計が 1 になるように直してから選ぶ。
  • top-p: 確率の大きい順に足していき、累積が p 以上になるまでの候補を残して選ぶ。

事前学習のあと、目的に合ったデータで追加学習して調整するのがファインチューニングです。ゼロから学習するより少ないデータで、特定の目的や話し方に合わせられます。対話向けのモデルでは RLHF(人間のフィードバックによる強化学習)も使われます。人がどちらの応答がよいかを比べたデータで報酬モデルを学習し、その報酬が高くなるように、強化学習で言語モデルを調整します。

モデルが一度に扱えるトークン数の上限をコンテキスト長といいます。多くのモデルでは、入力と出力を合わせたトークン数がこの上限以内でなければなりません。

事前学習・ファインチューニング・RLHF などの学習の段階と、プロンプトや RAG などの使い方は、LLMの学習と活用でくわしく扱います。

しくみ: 拡散モデル(画像の生成)

画像の生成でよく使われるのが拡散モデルです。考え方は「ノイズを足すのは簡単なので、その逆の、ノイズを取り除く方法を学ばせる」です。

  1. ノイズを足す(前向き): 本物の画像に、正規分布のノイズ(正規分布)を少しずつ足していく。何段階も足すと、元の画像がわからない、ただのノイズになる。これは計算だけでできるので、学習用の問題がいくらでも作れる。
  2. ノイズの取り除き方を学ぶ: モデルに「ノイズが足された画像」と「何段階目か」を見せ、足されたノイズを当てさせる。損失は、予想したノイズと本当のノイズの差の2乗(MSE)。
  3. 生成(後ろ向き): ただのノイズから出発し、モデルが予想したノイズを少しずつ引く、を何回もくり返すと、画像が浮かび上がる。
ノイズを足した画像=a × 元の画像 + b × ノイズ ε

よく使われる形では a2 + b2 = 1 で、段階が進むほど a が小さく、b が大きくなります。ε(イプシロン)は正規分布のノイズ。

画像の1つ1つのピクセルを直接あつかうと計算が重いので、画像をいったん小さな表現(潜在表現)に圧縮し、その上で拡散を行う方法もよく使われます。生成は1回の計算ではなく何回ものくり返しなので、LLM の1トークンずつの生成と同じく、手順の数だけ時間がかかります。

しくみ: 画像生成とテキストの条件

「夕焼けの海を描いた水彩画」のような文章(プロンプト)から画像を作るときは、文章をまずテキストエンコーダでベクトルの列に変え、ノイズを取り除くモデルに条件として渡します。モデルは、ノイズを予想するたびに注意(attention)などでこの条件を参照するので、文章に合う方向へ画像が仕上がっていきます。

条件ありの予想と条件なしの予想を比べ、その差の向きに強めに進めるガイダンスという工夫もよく使われます。強くすると文章に忠実になりやすいかわりに、画像の多様さや自然さが下がることがあります。温度と同じく、「強ければよい」というつまみではありません。

しくみ: ハルシネーションはなぜ起きるか

LLM は「学習データの中でありそうな続き」を確率で選んでいて、文を作るたびに事実を確かめているわけではありません。そのため、次のような場面で、事実と異なる内容をもっともらしく作ることがあります(ハルシネーション)。

  • 学習データにほとんど出てこない、めずらしい事実(細かい数値、人名、論文名など)。
  • 学習したあとに起きた出来事。モデルの知識は、学習データを集めた時点で止まっています。
  • 「わからない」と答えるより、それらしい答えを続けるほうが確率の高い流れになっているとき。

減らす工夫には、信頼できる資料を検索して入力に入れる RAG、出典を示させて人が確かめる、「わからない場合はそう答える」よう指示する、などがあります。どれも完全には防げないので、重要な内容は人が確認します(LLMの学習と活用)。

例で確かめる

例1: ソフトマックスと温度(上の図)

ロジット (2, 1, 0)。e2 ≒ 7.389、e ≒ 2.718。

  1. T = 1: 和は 7.389 + 2.718 + 1 ≒ 11.107。晴れ = 7.389 ÷ 11.107 ≒ 0.67、曇り ≒ 0.24、雨 ≒ 0.09。
  2. T = 2: ロジットを 2 で割って (1, 0.5, 0)。e0.5 ≒ 1.649 なので、晴れ = 2.718 ÷ (2.718 + 1.649 + 1) ≒ 0.51。
  3. ロジット (3, 2, 1) は (2, 1, 0) に 1 を足しただけなので、確率は同じ 0.67、0.24、0.09。

例2: top-k と top-p

次のトークンの確率が「A 0.4、B 0.3、C 0.2、D 0.1」のとき。

  1. top-k(k = 3): A・B・C を残す。合計 0.9 で割り直すと A ≒ 0.444、B ≒ 0.333、C ≒ 0.222。
  2. top-p(p = 0.75): 大きい順の累積は 0.4 → 0.7 → 0.9。0.75 以上になるのは3つ目なので、残るのは 3つ(A・B・C)。

例3: コンテキスト長

上限 4096 トークン、入力 3000 トークンなら、出力に使えるのは最大 4096 − 3000 = 1096 トークン。

例4: ノイズを足して、取り除く(ピクセル1つだけで)

元のピクセルの値 1.0、ノイズ ε = 0.5、a = 0.8、b = 0.6(0.82 + 0.62 = 0.64 + 0.36 = 1)。

  1. ノイズを足す: 0.8 × 1.0 + 0.6 × 0.5 = 1.1。
  2. モデルがノイズを 0.5 と正しく当てたら、元に戻せる: (1.1 − 0.6 × 0.5) ÷ 0.8 = 0.8 ÷ 0.8 = 1.0。
  3. 実際の生成では、一度に戻さず、少しずつ引くことをくり返します。

例5: 識別モデルか、生成モデルか

  1. 写真を見て「猫」「犬」を当てる → 識別モデル(入力 → 答え)。
  2. 「猫の写真」という条件から、新しい写真を作る → 生成モデル(条件 → データ)。
  3. 文章の続きを1トークンずつ確率で選んで書く LLM → 生成モデル。

よくある誤解・注意

  • 文章全体を一度に決めているわけではない。1トークンずつ、前から順に選んでいます。
  • もっともらしい = 正しい、ではない。LLM は「ありそうな続き」を生成するので、事実と異なる内容や存在しない出典をもっともらしく作ることがあります(ハルシネーション)。重要な内容は出典で確かめます。信頼できる資料を検索して入力にふくめる RAG も、減らす工夫の1つです。
  • ロジットが負でも確率は 0 にならない。e の何乗かは必ず正なので、どの候補にも 0 より大きい確率が残ります。
  • 温度を上げるほど良い、ではない。多様にはなりますが、ありそうもない語も選ばれやすくなります。
  • 拡散モデルは1回で絵を描くのではない。ノイズから少しずつノイズを取り除く手順を、何回もくり返して画像にします。
  • 生成AIは、学習データをそのまま貼り合わせているわけではない。分布を学んで新しく作りますが、学習データによく似たものを出してしまうこともあるので、権利や個人情報には注意が必要です。

しくみ1: トークン化(サブワードと BPE)

LLM は文字を直接は扱えないので、まず文章をトークンに区切り、1つ1つを番号(トークンID)に置きかえます。区切り方を決めるのがトークナイザーで、使えるトークンの一覧を語彙といいます。

単語ごとに区切ると語彙が巨大になり、辞書にない語を表せません。1文字ずつ区切ると、どんな語も表せるかわりに列が長くなりすぎます。そこで多くの LLM は、その中間のサブワードを使います。よく出る語は1トークン、めったに出ない語は部品に分けて表します。

サブワードの語彙を作る代表的な方法が BPE(バイトペア符号化)です。1文字ずつに分けた状態から始め、「学習用の文章の中で、いちばん多く隣り合っている2つの組」を1つの新しいトークンにまとめる、を決めた回数(語彙が決めた大きさになるまで)くり返します。

トークン数は、文字数とも単語数とも一致しません。日本語は、トークナイザーによっては同じ内容の英語よりトークン数が多くなることがあります。コンテキスト長の上限や料金・処理時間はトークン数で決まるので、文字数ではなくトークン数で考えます。

しくみ2: 語彙と埋め込み

トークンIDは単なる番号で、番号の大小に意味はありません。そこで埋め込み表(語彙数 × 次元 d の行列)を用意し、ID の行を取り出して、そのトークンのベクトルにします。これが埋め込みです。表の中身は学習で決まり、意味や使われ方の近いトークンほど、近い向きのベクトルになっていきます。向きの近さはコサイン類似度で測ります(コサイン類似度)。

数学メモ「行を取り出す」は、行列の積でも書ける

  1. ワンホットID の位置だけ 1、ほかは 0 のベクトル。ID = 1(0 から数えて2番目)なら (0, 1, 0)。
  2. (1×3) × (3×2)1列目: 0 × 0.1 + 1 × 0.9 + 0 × (−0.4) = 0.9。2列目も同じく 0.2。結果は 1×2(形の決まり)。
  3. = E の2行目0 をかけた行は消えるので、2行目がそのまま出てくる。実際の計算では、かけ算をせずに行を引くだけで済ませる。

よく知られた例に「王 − 男 + 女 ≒ 女王」があります。男 → 女 の向きの差を王に足すと、女王の近くに来る、というように、ベクトルの差が「関係」を表すことがあります。ただし、いつもきれいに成り立つわけではありません。実験室の「埋め込み」では、2次元の模型で内積・コサイン類似度・足し引きを試せます。実際の埋め込みは数百〜数千次元です。

しくみ3: 位置の情報

自己注意は、トークンの並びを入れかえても同じように計算されます。このままでは「ねこ が いぬ を 追う」と「いぬ が ねこ を 追う」の区別がつきません。そこで、何番目かを表すベクトル(位置埋め込み)をトークンの埋め込みに足したり、位置に応じてクエリとキーを回転させたりして、位置の情報を入れます。方式はモデルによってちがいます。

例: 位置埋め込みを足す

「ねこ」の埋め込み (1, 2) に、3番目の位置を表すベクトル (0.5, −1) を足すと、(1 + 0.5, 2 − 1) = (1.5, 1)。同じ「ねこ」でも、別の位置なら別のベクトルになります。

しくみ4: 自己注意(クエリ・キー・バリュー)

自己注意は、各トークンが「文中のどのトークンの情報を、どれだけ取りこむか」を決めて混ぜる計算です。各トークンのベクトル x に、学習で決まる3つの重み行列をかけて、3種類のベクトルを作ります。

  • クエリ q = xWQ: 「自分はどんな情報を探しているか」。
  • キー k = xWK: 「自分はどんな情報を持っているか」(見出し)。
  • バリュー v = xWV: 「選ばれたら渡す中身」。

ここでは xW(横に並べたベクトル × 行列)と書いていますが、ほかの単元の Wx(行列 × 縦に並べたベクトル)と、書き方の向きがちがうだけで、やっていることは同じ「行列とベクトルの積」です(行列とベクトルの積)。Transformer の説明では、トークンを1行ずつ積み重ねるので、この向きで書くことが多くあります。

クエリとキーの内積で関連の強さ(スコア)を出し、ソフトマックスで重みにして、バリューを重み付き平均します。全トークンぶんを行列でまとめて書くと、次の1行になります。

注意の出力=softmax(QKT√d) V

数学メモ行列の形を追いながら読む(トークン n 個、次元 d)

  1. Q、K、V(n×d)各トークンの q・k・v を1行ずつ積み重ねた行列。
  2. KT(d×n)K の転置(行と列を入れかえたもの)。
  3. QKT(n×n)i 行 j 列が「i 番目のクエリ · j 番目のキー」の内積。すべての組のスコアの表。
  4. ÷ √d、softmax大きさをそろえ、行ごとにソフトマックスで重み(各行の合計 1)にする。
  5. × V(n×d)(n×n) × (n×d) → n×d。各トークンに、バリューの重み付き平均が1本ずつできる。入力と同じ形にもどる。

1組の Q・K・V で注意を1回計算するかわりに、次元を分けて何組も並行して計算するのがマルチヘッド注意です。次元 768 を 12 ヘッドに分けると、1ヘッドは 768 ÷ 12 = 64 次元。ヘッドごとに、文法上の関係・意味の関係など、ちがう種類の関連を見られます。最後に全ヘッドの出力をつなげて 768 次元にもどし、出力用の重み行列 WO をかけます。実験室の「自己注意」で、重みが決まるようすを動かして見られます。

しくみ5: 因果マスク(先を見ない)

文章を作るとき、まだ書いていない先のトークンは存在しません。学習のときも同じ条件にするため、LLM の自己注意では、各トークンが自分と自分より前のトークンだけを見るようにします。これが因果マスクです。先のトークンのスコアを −∞ にしてからソフトマックスにかけると、e−∞ = 0 なので重みが 0 になります。

クエリ \ キー今日は晴れです
今日○×××
は○○××
晴れ○○○×
です○○○○

○ は見られる(重みが 0 より大きい)、× は −∞ にして重みを 0 にする組。4トークンなら ○ は 1 + 2 + 3 + 4 = 10 組。

マスクのおかげで、1つの文章から「今日 → は」「今日 は → 晴れ」「今日 は 晴れ → です」の予測問題を、1回の計算でまとめて学習できます。どの位置も、自分より先の答えを見ていないからです。

しくみ6: Transformer ブロック(注意 → FFN、残差接続、正規化)

LLM の本体は、同じ形のTransformer ブロックを何層も(数十層になることも)重ねたものです。1つのブロックの中では、次の2つを順に行います。

  1. 自己注意: トークンどうしの間で情報を混ぜる(上で見た計算)。
  2. FFN(フィードフォワード層): トークンごとに別々に、2層の全結合層でベクトルを変換する。次元をいったん4倍ほどに広げ、活性化関数を通して、元にもどすことが多い。

それぞれに残差接続(出力 = x + 層の計算(x))と正規化がつきます。残差接続があると、各層は「入力にどれだけ足すか」だけを学べばよく、勾配も入力側まで伝わりやすくなります(勾配消失)。正規化(層正規化など)は、ベクトルの値の大きさをそろえて学習を安定させます。正規化を注意や FFN の前に置くか後に置くかは、モデルによってちがいます。

数学メモ正規化は「平均 0、ばらつき 1 にそろえる」

  1. ベクトル (2, 4, 6)1つのトークンのベクトルの中で計算する。平均は 4。
  2. 平均を引く(−2, 0, 2)。
  3. 標準偏差で割る分散 = (4 + 0 + 4) ÷ 3 ≒ 2.667、標準偏差 ≒ 1.633(標準偏差)。割ると ≒ (−1.22, 0, 1.22)。

このあと、学習で決まる倍率とずらし幅をかけて足します。値が層を重ねるうちに大きくなりすぎたり小さくなりすぎたりするのを防ぎます。

しくみ7: 出力層(語彙サイズのロジット)

最後のブロックを出たベクトル(次元 d)に、d × 語彙数 の行列をかけると、語彙のすべてのトークンについて1つずつスコア(ロジット)が出ます。語彙が 32000 なら 32000 個です。これをソフトマックスにかけたものが「次のトークンの確率」で、温度・top-k・top-p で1つを選びます(生成AIのしくみ)。生成のときに使うのは、列のいちばん後ろの位置の出力です。出力層の行列は、埋め込み表と共有することもあります。

しくみ8: パラメータ数の見積もり

ブロック1層のパラメータは、次のようにおおまかに見積もれます(バイアスや正規化の分は小さいので除く)。

  • 自己注意: WQ・WK・WV・WO の4つが d × d → 4d2。
  • FFN: d → 4d と 4d → d の2つ → 4d2 × 2 = 8d2。
ブロック全体≒12d2 × 層の数+ 埋め込み表(語彙数 × d)

FFN の広げる倍率やヘッドの組み方はモデルによってちがうので、あくまで目安です。

しくみ9: コンテキスト長と計算量、KVキャッシュ

自己注意のスコアは、トークンのすべての組(n × n)について計算します。そのため、コンテキストの長さ n が2倍になると、スコアの計算は約4倍(長さの2乗に比例)になります。長い文章を入れると急に重くなる理由の1つです。

文章を1トークンずつ生成するとき、因果マスクのおかげで、過去のトークンのキーとバリューは、あとから何が足されても変わりません。そこで、一度計算したキーとバリューを保存しておき、新しいトークンの分だけを計算します。これが KVキャッシュです。計算は大きく減りますが、そのぶんメモリを使い、文脈が長いほど比例して増えます。

KVキャッシュの大きさ≒2(キーとバリュー)× 層の数 × トークン数 × d × 1つの数のバイト数

例で確かめる

例1: BPE で組をまとめる

「ねこねこねこいぬ」を1文字ずつに分けた、ね・こ・ね・こ・ね・こ・い・ぬ(8トークン)から始める。

  1. 隣り合う組を数える: 「ね こ」が 3 回、「こ ね」が 2 回、「こ い」「い ぬ」が 1 回ずつ。
  2. 最も多い「ね こ」を新しいトークン「ねこ」にまとめる: ねこ・ねこ・ねこ・い・ぬ で 5トークン。
  3. 次は「ねこ ねこ」が 2 回で最多なので、もう1回まとめるなら「ねこねこ」が語彙に入る。これを語彙が決めた大きさになるまで続ける。

例2: 因果マスクつきの自己注意(3トークン、d = 2)

トークンクエリ qキー kバリュー v
ねこ(1, 0)(1, 0)(4, 0)
が(0, 1)(0, 1)(0, 2)
走る(1, 1)(1, 1)(2, 4)
  1. 「ねこ」は自分しか見られないので、重みは 1。出力は (4, 0) そのまま。
  2. 「が」: 内積は ねこ 0、が 1。√2 で割って 0、≒ 0.707。e0 = 1、e0.707 ≒ 2.028 なので、重みは ≒ 0.33、0.67。出力 ≒ 0.33 × (4, 0) + 0.67 × (0, 2) ≒ (1.32, 1.34)。
  3. 「走る」: 内積は 1、1、2。√2 で割って ≒ 0.707、0.707、1.414。e の何乗かは ≒ 2.028、2.028、4.113(和 ≒ 8.169)。重みは ≒ 0.25、0.25、0.50。出力 ≒ 0.248 × (4, 0) + 0.248 × (0, 2) + 0.503 × (2, 4) ≒ (2.0, 2.51)。
  4. マスクがなければ、「ねこ」も先の「が」「走る」を見てしまいます(重み ≒ 0.40、0.20、0.40)。

例3: パラメータ数を見積もる

次元 d = 768、12 層、語彙 50000 のモデル。

  1. 1層: 12 × 7682 = 12 × 589,824 = 7,077,888。
  2. 12 層: 7,077,888 × 12 = 84,934,656(約 8500万)。
  3. 埋め込み表: 50000 × 768 = 38,400,000。
  4. 合計 ≒ 84,934,656 + 38,400,000 = 123,334,656(約 1.2億)。

例4: 長さの2乗と、KVキャッシュの量

  1. コンテキストを 1000 → 4000 トークン(4倍)にすると、スコアの数は 1,000,000 → 16,000,000 で 16倍。
  2. KVキャッシュ: 12 層、d = 768、1000 トークン、1つの数を 2 バイトで保存。2 × 12 × 1000 × 768 × 2 = 36,864,000 バイト ≒ 37 MB。トークンが 2000 になれば約 74 MB と、長さに比例して増える。

よくある誤解・注意

  • 1トークン = 1文字、でも 1単語、でもない。区切り方はトークナイザーしだいで、同じ文章でもモデルによってトークン数が変わります。
  • トークンID の大小に意味はない。意味を持つのは、埋め込みのベクトルです。
  • ソフトマックスは行ごと。注意の重みは、1つのクエリ(行)について合計 1 になります。表全体で合計 1 ではありません。
  • 注意の重みは、そのままモデルの「理由」ではない。どこに重みが大きいかはヒントになりますが、層やヘッドが多く、出力の理由をそれだけで説明することはできません。
  • KVキャッシュは計算を減らすが、メモリを使う。長い文脈ほど、層の数とトークン数に比例して増えます。
  • 2次元の埋め込みの図は模型。実際は数百〜数千次元で、「王 − 男 + 女 ≒ 女王」のような関係も、いつも成り立つわけではありません。

しくみ1: 事前学習

事前学習では、大量の文章を使って、次トークン予測をひたすらくり返します。正解(次のトークン)は文章そのものの中にあるので、人がラベルをつけなくても学べます(自己教師あり学習)。損失は、正解のトークンにつけた確率 p の −ln p(交差エントロピー)の平均です。

数学メモ損失とパープレキシティ

損失=1n Σ(−ln pi)パープレキシティ = e損失
  1. pii 番目の位置で、正解のトークンにモデルがつけた確率。
  2. −ln pi確率が 1 なら 0、低いほど大きい(ln)。
  3. 1n Σ全部の位置で平均する。
  4. e損失パープレキシティ。「平均すると何択で迷っているか」の目安。どの位置でも 4 択を等しく迷うなら、損失 ln 4 で、パープレキシティ 4。

事前学習を終えたモデルは、文章の続きを書くのは得意ですが、質問に答える・指示に従うといった話し方はまだ身についていません。

しくみ2: スケーリング則の考え方

パラメータ数・学習データの量・計算量を大きくすると、損失がなめらかに下がっていく傾向が、さまざまな実験で見られています。この関係が、べき乗の形の式でよく近似できるという経験則をスケーリング則といいます。べき乗の関係では、たとえば「パラメータを10倍にするたびに、損失がほぼ同じ割合で下がる」ので、両方の軸を対数にしたグラフでは直線に近くなります。

  • 下がり方はしだいにゆるやかになり、同じだけ下げるには、何倍もの規模が必要になります。
  • 計算量が決まっているとき、パラメータとデータのどちらにどれだけ配るかで結果が変わります。片方だけを大きくしても効率がよくありません。
  • 損失が下がることと、使いたい用途で役に立つことは別です。データの質や評価も、あわせて確かめます。

学習の計算量の目安として、「6 × パラメータ数 × 学習トークン数」回の計算、という見積もりがよく使われます。

しくみ3: 指示チューニング(SFT)

事前学習したモデルに、「指示や質問」と「よい応答」の組をたくさん見せて追加学習します。これを指示チューニング(教師ありファインチューニング、SFT)といいます。学習のしかたは次トークン予測と同じで、データが「指示 → 応答」の形にそろえてあるのがちがいです。損失は、応答の部分のトークンだけで計算することがよくあります。

しくみ4: 人の好みに合わせる調整(RLHF・DPO)

「どちらの応答がより役に立つか・安全か」は、1つの正解を決めにくい問題です。そこで、人が2つの応答を比べた比較データを使って調整します。

  • RLHF(人間のフィードバックによる強化学習): 比較データで報酬モデル(応答の良さに点数をつけるモデル)を学習し、その点数が高くなるように、強化学習で言語モデルを調整する。元のモデルから離れすぎないようにする工夫も加える。
  • DPO: 同じ比較データから、報酬モデルを別に作らず、好ましい応答の確率が相対的に上がるようにモデルを直接学習する方法。

しくみ5: プロンプトの工夫

モデルの重みを変えずに、入力(プロンプト)の書き方で答えを引き出す方法です。

  • ゼロショット: 例を入れず、指示だけで聞く。
  • 少数例(few-shot): 「入力 → 答え」の例をいくつか書いてから本題を聞く。答えの形やルールをまねさせやすい。例の分だけ入力のトークンが増える。
  • 段階的に考えさせる: 「途中の考えを順に書いてから答えて」と頼む。モデルは自分が出力したトークンも次の予測の材料にできるので、計算や推論の問題で正しくなりやすいことがある。ただし途中の説明が正しいとは限らず、出力が長くなる分だけ時間もかかる。
  • 役割・目的・出力の形(箇条書き、表、文字数)・してほしくないこと、を具体的に書く。あいまいな指示ほど、答えもぶれます。

例: 少数例(few-shot)のプロンプト

  1. 「次の感想が、肯定か否定かを答えてください。」
  2. 「感想: とても使いやすい → 肯定」「感想: すぐに壊れた → 否定」(例を2つ)
  3. 「感想: 思ったより静かで快適 →」(本題。モデルは例の形をまねて「肯定」と続けやすい)

しくみ6: RAG(検索して文脈に入れる)

LLM の知識は学習した時点で止まっていて、社内文書のような学習データにない情報も知りません。RAG(検索拡張生成)は、質問に関係する資料を検索し、プロンプトに入れてから答えさせる方法です。モデルの重みは変えません。

入れられる資料の量は、コンテキスト長で決まります。指示・質問・回答の分をあけておき、残りに資料を入れます。資料が多すぎると、大事な部分が埋もれたり、計算が重くなったりします。

しくみ7: ツール利用とエージェント

LLM は文章しか出力できませんが、「検索する: ○○」「計算する: 123 × 456」のような決まった形の呼び出しを出力させ、それを外のプログラムが実行して結果を入力にもどせば、検索・計算・ファイル操作などができます。これがツール利用です。計算のように、LLM が苦手で道具なら確実な作業を任せられます。

「計画する → ツールを使う → 結果を見る → 次を決める」を何回もくり返して作業を進めるしくみをエージェントといいます。手順が長いほど、途中の小さな誤りが積み重なりやすくなります。使えるツールは必要なものだけに絞り、取り消せない操作(送信・削除・支払いなど)の前には人が確認するように作ります。

しくみ8: ファインチューニングと LoRA

特定の用途や話し方に合わせるため、目的のデータで追加学習するのがファインチューニングです。すべての重みを学習しなおすと、計算もメモリも多く必要で、用途ごとにモデル全体を保存することになります。

LoRA は、元の重み行列 W を固定したまま、細長い2つの行列の積 BA を足して、その小さな行列だけを学ぶ方法です。

使う重み=W(固定)+ BA(学ぶ)

数学メモ形を追うと、なぜ少なくてすむかがわかる

  1. W(d×d)元の重み。d = 1000 なら 1,000,000 個。
  2. B(d×r)、A(r×d)r は 8 などの小さな数(ランク)。
  3. BA(d×d)(d×r) × (r×d) → d×d で、W と同じ形になるので足せる(形の決まり)。
  4. 学ぶ数 = 2dr2 × 1000 × 8 = 16,000 個。元の 1,000,000 個の 1.6%。

知識を足したいだけなら、ファインチューニングより RAG のほうが向いていることも多くあります。ファインチューニングは、答え方の形や口調、特定の作業のやり方を身につけさせたいときに向いています。

しくみ9: 評価(ベンチマークの限界と汚染)

LLM の性能は、決まった問題集(ベンチマーク)の点数で比べることがよくあります。ただし、次の限界があります。

  • ベンチマークは決まった形式の問題での成績にすぎず、自分の使いたい場面で役に立つかは別です。
  • 大量の Web の文章で学ぶため、公開された問題と答えが学習データにまぎれこむことがあります(汚染、コンタミネーション)。答えを覚えているだけなら、点数は本当の力より高く出ます。
  • プロンプトの書き方や採点のしかたで点数が変わります。比べるときは条件をそろえます。

使う前には、自分の用途に近い問題を集めた評価セットを作り、人の目でも確かめるのが確実です。

しくみ10: ハルシネーション対策と安全性

ハルシネーション(生成AIのしくみ)を減らすには、RAG で根拠の資料を与える、出典を示させる、わからないときは「わからない」と答えるよう指示する、答えを別の方法で確かめる、などを組み合わせます。どれも完全ではないので、重要な判断には人の確認を入れます。

  • プロンプトインジェクション: Web ページ・メール・文書の中に「これまでの指示を無視して〇〇せよ」のような文がまぎれていると、モデルがそれを指示と取りちがえることがあります。モデルにとって、もとの指示と、取りこんだ文章の中の「指示らしい文」を区別するのはむずかしいからです。完全に防ぐ方法はまだないので、ツールの権限を絞る・重要な操作の前に人が確かめる・取りこんだ内容と指示を分けて扱う、を組み合わせて被害を小さくします。
  • 偏り: モデルは学習した文章の傾向を引きつぐので、性別・国・職業などについて偏った表現が出ることがあります。
  • 個人情報・機密: 入力した内容がどう扱われるかはサービスによってちがいます。規約を確かめ、自分や他人の個人情報・機密はむやみに入れません。

例で確かめる

例1: 事前学習の損失とパープレキシティ

3つの位置で、正解のトークンにつけた確率が 0.5、0.25、0.8。

  1. −ln 0.5 ≒ 0.693、−ln 0.25 ≒ 1.386、−ln 0.8 ≒ 0.223。
  2. 平均: (0.693 + 1.386 + 0.223) ÷ 3 ≒ 0.767。
  3. パープレキシティ: e0.767 ≒ 2.15。平均すると約2つの候補で迷っている程度。

例2: RAG の検索と、入れられる量

質問のベクトル (2, 1)。断片 A (1, 0)、B (2, 2)、C (−1, 2)、D (3, 1)。

  1. コサイン類似度: A ≒ 0.894、B ≒ 0.949、C = 0(内積 −2 + 2 = 0)、D ≒ 0.990。
  2. 上位2件は D と B。C は質問と直角の向きで、関係が薄いと判断される。
  3. コンテキスト長 8000、指示 300、質問 200、回答用に 1000 あけると、資料には 8000 − 300 − 200 − 1000 = 6500 トークン。1つ 500 トークンの断片なら 6500 ÷ 500 = 13 個まで。

例3: 学習の計算量の目安

パラメータ 1億(108)、学習トークン 100億(1010)なら、6 × 108 × 1010 = 6 × 1018 回(指数は足し算: 8 + 10 = 18)。

例4: 汚染で点数が高く出る

100 問のベンチマークのうち 30 問が学習データにまぎれていた。まぎれた問題の正解率 90%、まぎれていない問題の正解率 60%。

  1. 全体の正解率: 0.3 × 90% + 0.7 × 60% = 27% + 42% = 69%。
  2. 見たことのない問題での力は 60% なのに、9 ポイント高く見える。

よくある誤解・注意

  • プロンプトや RAG は、モデルを学習しなおしていない。重みは変わらず、入力が変わるだけです。会話が終われば、その情報は残りません(サービス側の記憶機能などは別です)。
  • RAG を使えばハルシネーションがなくなる、ではない。検索で関係のない資料を拾ったり、資料にないことを足したりすることがあります。出典を確かめます。
  • 大きいモデルほど何でも正しい、ではない。スケーリング則は損失の傾向で、個々の答えの正しさを保証するものではありません。
  • ベンチマークの点数 = 自分の用途での実力、ではない。汚染や形式のちがいがあります。
  • エージェントに大きな権限を渡しすぎない。プロンプトインジェクションや誤りが、そのまま実際の操作になってしまいます。
